Module defaults at a glance+

The builder starts with these defaults. Any omitted built-in trigger is enabled by the module, so the generator explicitly writes enabled: false for moments you turn off.

Setting Default What it means
Page end 90% Scroll down to this page depth.
Return to top 10% Scroll deeper first, then return upward to this threshold.
Time on page 60 seconds Elapsed time, including active reading.
Tab / app return 1 second away Show on return after the minimum time away.
Custom event Off Register your own event when needed.
Close button On · 3 seconds A countdown appears before the button is usable.
Repeat interval 60 seconds Per moment, measured from its last successful display.
Page / session / day caps 5 / 5 / 10 Shared across all moments and manual displays.
Prepare a bid before the moment arrives+

Optional prefetch points can start the auction early. Add these properties under display.trigger for the moments you enable.

JAVASCRIPT · DISPLAY.TRIGGER 
bottomOfPage: {
  enabled: true,
  threshold: 90,
  prefetchAtThreshold: 70
},
returnToTop: {
  enabled: true,
  threshold: 10,
  prefetchAtThreshold: 50
},
idleTime: {
  enabled: true,
  minTime: 60000,
  prefetchAtTime: 45000
}

For page end, prefetch before the display depth. For return to top, the reader must first pass the prefetch depth, then cross it upward; set it above the display threshold. For time on page, prefetchAtTime must be below minTime. Time values in code are milliseconds.

Connect a custom event or trigger directly+

When you enable “Your own event,” the generator registers a listener and a cleanup function. Your site still needs to dispatch that event. For example, connect your video player’s completion handler:

JAVASCRIPT 
// Replace #my-video with your video element’s selector.
const video = document.querySelector('#my-video');
if (video) {
  video.addEventListener('ended', function () {
    window.dispatchEvent(new Event('video-complete'));
  });
}

Use the same event name in your configuration. You can also call window.pbjs.exitAds.trigger() after Prebid has loaded. Both custom and manual requests respect the global display interval and frequency caps.

For conditions you can check directly, use a custom polling trigger. The module checks it once per second. Choose polling or an event setup for your custom moment.

JAVASCRIPT · DISPLAY.TRIGGER 
custom: {
  enabled: true,
  repeatInterval: 60000,
  condition: function () {
    return window.readerState?.articleComplete === true;
  }
}
Frequency limits and repeat timing+

Page caps reset on page reload. Session caps use the current tab’s session storage. Daily caps use local storage and reset on the browser’s next local calendar day. Only Prebid-confirmed successful renders consume caps. Prefetches, no-bid outcomes, suppressed attempts, and failed renders do not.

Each moment’s repeatInterval is measured from its own last successful display. Use null for once per page load, or 0 to rely on the global 30-second gap. Closing an ad restarts that global gap. These intervals are separate from the total number of ads allowed.

Ad sizes and presentation+

Exit Ads supports banner ads. The builder selects one eligible banner size. Your integration can supply more than one in adUnit.mediaTypes.banner.sizes, for example [[300, 250], [300, 600]]. Include sizes appropriate to your pages and placements.

The close button is enabled by default. Set display.closeButton.delay to 0 for immediate closing. Its countdown rounds up to whole seconds. Additional styles go in display.cssOverrides, using the module’s stable classes:

JAVASCRIPT · DISPLAY.CSSOVERRIDES 
cssOverrides: `
  .exit-ads-overlay { background: rgba(12, 30, 25, 0.85); }
  .exit-ads-container { border-radius: 12px; }
  .exit-ads-close-button { background: #203c33; }
`
Auction settings+

Add optional auction settings alongside adUnit and display inside exitAds. Exit Ads otherwise uses your Prebid auction timeout.

Setting Use
timeout Maximum auction wait, in milliseconds.
labels Array of labels for Prebid size or configuration selection.
ortb2 First-party data for this auction.
Storage and consent+

Frequency limits use browser storage when available. Add storage alongside adUnit and display to choose how those counters are stored.

Setting Default Use
mode auto Use memory to keep counters only in the current page.
prefix exitAds Namespace for the module’s storage keys.
canAccess Unset Optional callback that checks your consent policy before each persistent storage access. Return false to use memory.

Prebid’s deviceAccess: false, denied storage, or unavailable browser storage also falls back to memory. In memory mode, session and daily counts do not survive a page reload.

Callbacks, troubleshooting, and configuration changes+

Add callbacks alongside adUnit and display inside exitAds to observe what happens.

Callback When it runs
onBidCached A bid has been received and cached.
onTrigger An eligible trigger starts or waits for an auction.
onAdRender Prebid confirms the winning creative rendered successfully.
onAdClose The reader activated the enabled close button.
onFrequencyCapReached A request was prevented by a frequency cap.
onTriggerSuppressed A request was suppressed; inspect its reason, such as noBid, renderFailed, or frequencyCap.

No bid means no ad. Check placement IDs, available demand, enabled moments, and frequency limits. Configuration updates via pbjs.setConfig() apply immediately, cleaning up old monitors, overlays, styles, and cached bids. Use pbjs.exitAds.reset() to reset page state and restart monitors, or pbjs.exitAds.destroy() for page teardown.
